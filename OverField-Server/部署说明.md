# OF_SF 服务端部署与存档

适用于国服 PC 1.1.12。Windows x64 与 Linux x86-64 各有独立发行包。下面的命令均在解压后的 `OverField-Server` 目录执行。

## 首次启动

解压到可写目录。Windows 运行 `.\Start-Server.cmd start`，Linux 在基于 glibc 的 x86-64 系统上运行 `./start.sh start`。两个发行包均附对应平台的 Python 运行时。需要验证新部署时，可在启动前运行自检并建立一个测试档案。

~~~sh
sh start.sh test
sh start.sh create-player --nickname 海星
sh start.sh start
~~~

在另一个终端验证运行情况。把示例中的路径替换为建档命令显示的 JSON 文件路径。使用 check-player 时请先断开这个角色的其他游戏会话。

~~~sh
sh start.sh health
sh start.sh check-player --profile state/profiles/实际档案.json
sh start.sh stop
~~~

Windows 将上述各行的 sh start.sh 换成 Start-Server.cmd。health 检查档案 HTTP 与玩法 TCP 监听器。check-player 使用本服档案申请一次性票据，通过原生 PacketHead/protobuf 读取登录、角色主数据和首帧场景。

## 对普通玩家开放

在第二个终端启动附带的玩家网关，给玩家提供 TLS 地址和 Windows 轻量补丁。玩家可直接使用本服账号注册和登录。证书、端口和各平台完整命令见[公网玩家接入](docs/公网玩家接入.md)。服主可给指定账号或 UID 授予[游戏内管理权限](docs/游戏内管理.md)。

## 档案与迁移

本服的独立昵称在建档事务中分配。未指定昵称时自动命名。默认关闭 HTTP 注册，本机管理员可以在运行期间建档。state/realm/ 下的 identity.sqlite3 保存私服身份，game.sqlite 保存角色、任务及物资。state/profiles/ 下的玩家 JSON 包含登录密钥，应逐个交给对应玩家并单独备份。需要调整数据目录时，可设置 OF_STATE。

先停服，再将存档导出为一个新名称的 ZIP。在目标机解压本发行包，将备份复制过去，恢复到空存档目录并启动。Linux 和 Windows 的备份格式相同。

~~~sh
sh start.sh stop
sh start.sh backup realm-backup.zip
~~~

~~~sh
sh start.sh restore realm-backup.zip
sh start.sh start
~~~

若要在目标机器直接检查已有角色，一并转移所需的玩家档案 JSON。恢复会核验备份摘要与数据库结构。

## 网络与容器部署

默认监听 127.0.0.1，档案 HTTP 使用 TCP 18881，玩法服务使用 TCP 11033。专网部署时把 OF_BIND 和 OF_GAME_HOST 设为实际专网 IPv4 地址。私服通信可通过受信 VPN。OF_HTTP_PORT、OF_GAME_PORT 可以修改端口。用 OF_HTTP_HOSTS 配置允许的其他 HTTP 主机名，用 OF_DISPATCH_URL 指定玩家可达的本服派发地址。档案 HTTP 支持 OF_TLS_CERT、OF_TLS_KEY，健康检查可通过 OF_HEALTH_HOST 指定证书上的主机名。

~~~sh
OF_BIND=10.8.0.5 OF_GAME_HOST=10.8.0.5 sh start.sh start
~~~

使用 Docker 时，首次构建需要本地已有基础镜像或能获取该镜像。启动后数据保存在 realm-state 卷。远程部署可为 Compose 设置 OF_PUBLISH_IP 和 OF_GAME_HOST。

~~~sh
docker compose build
docker compose run --rm realm test
docker compose run --rm realm create-player --nickname 海星
docker compose up -d
docker compose ps
~~~

## 原版资源派发

可将已有同版本完整客户端设为只读资源来源。本地文件路径由 OF_CLIENT_ROOT 指定。完整资源存在时，派发模块校验内置清单、补丁清单及 8,936 个活动资源包，并支持范围读取。默认未挂载时仍可测试本服档案、玩法与数据迁移。下例在服务启动前设置客户端根目录。

~~~powershell
$env:OF_CLIENT_ROOT = 'D:\TapTap\PC Games\176228'
.\Start-Server.cmd
~~~

Linux 可以使用 OF_CLIENT_ROOT=/srv/overfield-client。Docker 可用 Compose 的额外只读 bind mount 并在容器内指定对应路径。

## 独立原版副本的区服发现配置

国服 1.1.12 的 launcher_Data/data.unity3d 内，resources.assets 的 Config/InitConfigAsset 对象（PathID 2813）在 Release.LoginServer 字段记录了原始派发地址 http://dsp-prod-of.inutan.com:18881。随包的 47,218 字节差量可把这一字段导出为 http://127.0.0.1:18881/private-game。私服以此路径接收本机区服发现请求。

以下命令用随包 Python 从用户已有的同版本文件生成供独立原版副本使用的单个资源文件。输出须位于原安装目录外且使用新文件名或空目录。工具先校验原件，再校验生成结果。生成文件约 95 MB，完整客户端由用户另行保留。

~~~powershell
.\runtime-win64\python.exe -B .\docs\native-config\export_client_config.py "D:\TapTap\PC Games\176228\launcher_Data\data.unity3d" "$env:TEMP\OverField-native-config\launcher_Data\data.unity3d"
~~~

这个结果用于测试原版 Unity 的区服发现。同机可选的国服在线身份验证见 docs/联网验证.md。远程服务只使用自己的档案和游戏票据。


## 本版可验证的内容

自检在临时目录创建独立角色，启动本机测试监听器。覆盖原生首包、昵称和旧档补名、角色主数据、主城出生、同场移动、持久存档、私服设置、秘境、奖励及停服迁移。序章「新的伙伴」的两个咖啡厅对话会判定角色所处的 NPC 区域，写入任务并发送原始奖励。第三项目标支持教学首抽、诗的初始装备、编队及剧情领奖。具体的原版任务依据、触发范围和验证界限见 docs/序章新的伙伴.md。

原版游戏的资产和玩家存档请另行保留。服务端配置摘要见 resource-sources.json，运行时来源见 docs/RUNTIME.txt，社区代码许可见 LICENSE-of-ps.txt。基线与参考更新见 [byzp/of-ps 源码](https://github.com/byzp/of-ps/tree/fa2142b8521e802beb23fc6ed538205b9f4f1513) 和 [本次核对的上游版本](https://github.com/byzp/of-ps/tree/fe8904344ef376b21dd4c248e5072bf975b873d8)。

## 同服多人队伍

进入同一场景与频道后，队员可以向在线玩家发出邀请。受邀玩家有 120 秒加入队伍。队长可改名、更换已配置的游戏模式、踢人或解散队伍。队长退出后，由最早加入的现有成员接任。普通队员退出和踢出有不同结果，踢出会应用国服配置的再次加入冷却。成员和队长身份随存档迁移。

默认每队最多 16 人，队名最长 20 字符。服主停服后可用以下命令调整每队人数、队名长度和区服内的队伍总数。队伍总数设为 0 时不限。

```sh
./start.sh rules --mp-team-members 8 --mp-team-name-length 12 --mp-team-limit 100
```

Windows 使用 `Start-Server.cmd rules` 搭配相同参数。自动化工具也可在 `admin call rules.set` 的 JSON 对象中发送 `mp_team_members`（2 至 16）、`mp_team_name_length`（1 至 20）和 `mp_team_limit`（0 表示不限）。
