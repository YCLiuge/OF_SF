# 玩法排查索引

适用版本为 TapTap 国服 PC 1.1.12。跨渠道比较先记录安装基版和当前热更清单。游戏消息字段相同的客户端也可能使用不同的登录 SDK、音效或场景资源。

| 现象 | 从哪里查 | 已核实的行为与复验位置 |
| --- | --- | --- |
| 新角色缺探索员、武器或 UP 池 | `resources/data/Character.json`、`Weapon.json`、`Gacha.json`，登录主数据及招募列表处理器 | 区分可操作角色和 NPC、武器模板和装备实例、池的展示与可抽状态。核对新建和继承存档两条路径。[招募卡池](招募卡池.md) |
| 翻到角色、跳过动画或十连汇总卡住 | `app/upstream/private_gacha.py`、`private_gacha_rewards.py`，原版 `GachaSystem.ExChangeItem`、`UI_Gacha_ViewCtrl.ShowNextItem`、`Show_ItemInfo` | 在本机原版客户端抽「雾都侦探」限定十连，出现 SR 探索员「可」。点「跳过」后完整显示 #01–#10、TOTAL:10，前三项依次为可、兔、回味。点右上角 × 返回同池，限定券由 1,000,000 减至 999,990，保底计数由 70 减至 60。排查时逐张核对主物品、转换物、额外奖励和角色实例。见 `test_native_gacha_rewards.py`、`test_native_gacha_atomicity.py`。 |
| 家具拿起后定位线持续 | `private_garden_actions.py`、`private_channels.py`，本人 1684 回执、1698 场景通知、7001 手持回显 | 拿起→放下→再拿→切图→重登，核对自己和同房另一玩家的视图及背包件数。见 `test_private_channels.py`、`test_native_home_visibility.py`。[频道与家园](频道与家园设置.md) |
| F5 星云树停在「庭院之徽」「07」「23%」，节点全为「染色」 | `private_badge_tree.py`、`handlers/PlayerMainData.py`、国服 `UI_Root_MenuStone.prefab` | 这些文字是原版预制界面的初始值。客户端会筛选已开放的探索地图，再检查背包道具 100000008。旧区服提前开放入口，导致尚无可用地图的广场新号进入空界面。新版按芳汀教学 100031 开放，保留已有徽章或有效节点的角色。实机用 r7 登陆器将含二段跳的存档导入空白区服，进入樱庭后按 F5 显示「星符·樱庭」3%，点蓝色「二段跳」能查看技能说明，点 × 返回樱庭 3D 场景。另已复验退出再开仍显示 3%。见 `test_native_badge_tree.py`。祈愿树另见[祈愿树排期](祈愿树排期.md)。 |
| 管理员投递后收不到邮件，或附件重复入账 | `app/realm_mail.py`、`app/upstream/private_mail.py`、`app/admin_ui/mail_editor.js` | 在隔离区服用 `mail.send` 指定一个在线测试角色。原版游戏自动收到邮件，单领后显示「获得物品 金币 ×2」。复核区服只有一封邮件，状态为已领取，金币从 1,001,625 变为 1,001,627。群发、重试、离线重登及单领/全领回归见 `test_native_mail.py` 和[投递操作](服主公告与版本发布.md#投递游戏邮件)。 |
| 切全屏黑屏 | 登陆器「游戏显示模式」及 `client_tools/native_launch.py` | 本机在 TapTap 国服原版标题页按 Alt+Enter，从 1283 × 751 窗口（含窗框）切到 1707 × 960 全屏，再按一次返回窗口。进图后，在游戏设置中点「全屏幕」再切「窗口化」，设置页和罗塔广场均正常显示。其他显示器和无边框冷启动需分别复测。有黑屏时可从登陆器选择 1280 × 720 窗口模式恢复，并检查客户端 `Player.log` 的图形设备错误。 |
| 斧头普攻无声或缺第三段 | `Weapon`、`Spell`、`Gather`、`LifeGather` 数据表和客户端资源清单 | 先区分战斗大斧与生活伐木斧，记录武器、地图、轻点/按住、命中/空挥。「三连斩」「齿轮连击」有第三段，蓄力或旋转招式另测。对照原版与副本的音效和动画依赖。完整资源校验不能证明玩家现场有声音。 |
| 新玩家停在渠道登录页 | 区服账号登录记录，原版 NEKOTAN 渠道窗口 | 截图中的「TapTap登录」可用现有 TapTap 账号授权。区服账号由登陆器验证，渠道授权由原版处理。[发行方 PC 登录说明](https://www.taptap.cn/moment/656591245195346144) |

斧头资源可从源码仓库运行 `python tools/check_axe_assets.py "原版游戏目录" "登陆器工作目录/Client"`，按清单比对动作、音效与依赖并列出差异。[资源检查说明](公网玩家接入.md#斧头普通攻击与伐木排查)

## 区服维护

| 要确认的事 | 检查顺序 |
| --- | --- |
| 首次热更或标题页久等后无法进入 | 更新玩家补丁和区服。支持 `first_launch_wait_v1` 的区服会保留已验证账号的本次启动预约 60 分钟，客户端准备进图时再签发一次性游戏票。隔离区服实测等待 307 秒后仍可登录并读取角色和场景，再次兑换同一预约被拒绝。超过预约有效期时请从登陆器重新登录。 |
| 玩家是否能连入 | 在区服目录运行 `.\Start-Server.cmd health` 或 `./start.sh health` 检查进程，再从玩家端用对外域名测试连接。登录测试角色进图，分别确认账号网关和游戏连接。更新游戏进程时保持原有 SakuraFrp 隧道运行。[公网接入](公网玩家接入.md) |
| 在线上限与活动是否生效 | 在管理台「概览」读取当前在线数及准入上限，在「活动」保存排期后重新打开该项，核对时区和有效期，再从游戏查看对应入口。[活动管理](活动管理.md) · [本机管理接口](本机管理接口.md) |
| 如何验证更新与回退 | 记录现行版本、文件 SHA-256 和备份位置。先在独立数据目录验证候选版本。正式切换前确认玩家离线，正常停服并备份。回退时使用与备份匹配的程序，在空目录验证可恢复。[开服与迁移](../../README.md#开服与迁移) |
| 如何追踪投递和存档 | 用测试账号核对导入预览里的公开 UID、主线位置和背包。发游戏邮件后按批次查历史，在该账号的游戏收件箱核对附件领取与重登入账。[个人进度导入](个人进度导入.md) · [公告与邮件](服主公告与版本发布.md) |

## 复跑与留档

在已补齐本机资源的发行目录执行 `.\Start-Server.cmd test`，Linux 用 `./start.sh test`。以上测试文件位于 `tests/`。服务端通过原生请求回归后，再记录同版本原客户端是否完成对应的界面操作。[构建与资源准备](../../tools/BUILD.md)

新增条目记录客户端渠道、基版和热更、触发步骤、相关消息或资源、回归用例、实机结论。只见到玩家反馈时标为待复现；协议、资源或画面有新结果时就地更新。长期索引使用仓库相对路径和可分发的合成样本。私有存档、令牌、含账号信息的原始日志留在本地。
