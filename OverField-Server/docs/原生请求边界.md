# OF_SF 原生请求边界

本页按国服 PC 1.1.12 的消息字段、资源表和已验证的区服行为记录证据。实际路由数量见[客户端请求对照](客户端请求对照.md)。

| 原生操作 | 当前依据与处理 |
| --- | --- |
| 继承奖励码 `InheritCodeUseReq` | 玩家提交 `code`，响应回传 `code_str` 和物品明细。上游按 `inherit` 类型发奖。本服支持服主发码、限额、到期与撤销，双角色原生协议回归验证了只领一次和重登后的余额。码只给当前角色发奖。继承旧 UID、名字和进度使用[个人进度导入](个人进度导入.md)。零售客户端输入该码的界面尚待确认。 |
| 场景通用子消息 `GenericSceneAReq` | 四个通用请求共用子编号。国服枚举列出 9 项，已能确认天气预报走 SceneB。SceneA 的原版响应入口只分派热更新，上游回显参数。现有样本尚无法将一个具体动作归到 SceneA，这个请求仍返回失败。 |
| 取消绑定 `AccountNameBindingCancelReq` | 请求无参数，上游只回传当前 UID。国服设置页的解绑按钮显示手机解绑提示。OF_SF 的独立账号没有手机绑定记录，此操作返回失败，账号、UID、名字和存档均保留。 |
| 操作验证 `UnfreezePlayerActionReq` | 本服 GM 发送 `/gm challenge UID` 后，指定在线角色收到原生三位数操作验证。受限角色可以维持连接并提交答案，只有本人答对才恢复操作。断线或区服重启后继续验证。5 分钟超时或连续 5 次输错后换题。 |
| 秘境三星奖励 `DungeonStarRewardReq` | 国服 490 条副本记录中有 156 关配置三星时限，全部缺省星奖表号。默认维持关闭。服主选定奖励表后，按角色在本服实际完成的计时成绩判断。计时低于该关三星时限可领一次，副本任务奖和深渊赛季奖分别记账。旧档单有通关次数或时间戳不构成三星成绩。 |
| 坍塌地块 `CollapseFailReq` | 房间使用国服 10060101、10060102 关卡，两关共用同一个地块预制件，时长均为 60 秒。队员落下时仅向同房队员发送这名角色的 UID 淘汰通知。全员淘汰或到时结算。本服按存活记 1、淘汰或离开记 0，缺少国服奖励表，结算不发券。默认组队菜单仍有两项，坍塌另行启用。 |

服主关闭了五个入口。实物收货地址读取和提交占两项，发行方设备日志授权、日志上传占两项。第五项 `UploadFGBytesReq` 对应 FairGuard SDK 上传二进制数据，区服返回失败，丢弃该数据。

原生兑奖的参数与发码示例见[本机管理接口](本机管理接口.md)。[上游继承码](https://github.com/byzp/of-ps/blob/cc4dc52e1bcc9fcfb625b10c18ce0411e3eba709/handlers/InheritCodeUse.py) · [上游副本星级奖励](https://github.com/byzp/of-ps/blob/cc4dc52e1bcc9fcfb625b10c18ce0411e3eba709/handlers/DungeonStarReward.py)

## 启用可选玩法

停服后运行，随后启动同一份区服存档。Linux 将 `Start-Server.cmd` 换为 `./start.sh`。

```bat
Start-Server.cmd rules --enable-collapse-rooms 1
Start-Server.cmd rules --dungeon-star-reward-id 101
```

第二条命令是配置示例。当前 `Reward` 表的 101 号奖励发放 10 个 102 号道具，设为 0 即恢复客户端资源里的规则。坍塌开放后，队长在附近聊天输入 `/collapse`，再按原组队流程放置信标、召集和开始。取消预约用 `/collapse cancel`。人数与开场费用沿用原队伍所选课程，仅替换下一局。四角色原生协议测试已覆盖入场、淘汰广播、超时结算及异频道隔离。原客户端的坍塌画面与结算展示尚待实机确认。[上游多人房间协议](https://github.com/byzp/of-ps/blob/cc4dc52e1bcc9fcfb625b10c18ce0411e3eba709/proto/net.proto)
