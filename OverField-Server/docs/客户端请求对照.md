共 56 套隔离测试通过。服务端处理范围有时取决于同一请求中的操作类型。例如同一条连接提交 `AcceptQuestReq`，已解锁的序章主线会接取并返回具体任务 100011，使用同一主线编号提交额外剧情类型会返回参数错误。类型 0 的广场委托和限时活动对话已验证合法接取；类型 9 以额外故事的真实末步编号验证 24 份奖励结算。报告按套件保存实际观测的操作枚举与回应。角色升星用国服表要求的碎片，在测试角色上实扣实升，并核对数据库余量。移动上报走单向场景处理，本地交易入口关闭真实支付，这两项会分别体现在实际消息与状态码中。其余字段组合、嵌套消息、实际客户端渲染、发行方线上服务行为仍需逐项验证。

- **体力与精力**。四项原生查询和购买已测。体力每 600 秒恢复 1 点，达到该等级上限即停止，旧档从首次可信观察开始计时。体力、精力购买按各自阶梯扣费，每次最多补 60、200 点，补充到该等级上限为止，按国服时间 05:00 刷新次数。测试覆盖重登、跨日、余额不足、角色隔离、回滚，以及同一连接重发同一交易包。既有超上限余额会保留。精力自然恢复时间缺乏独立依据。

## 复查

从源码仓库根目录运行，生成的 JSON 为每个请求保留原始编号、响应编号、顶层字段、实际分派位置和回退状态。源码里的测试引用与隔离运行观测分别列出。重跑只使用临时角色和本机回环地址。

```sh
python tools/audit_requests.py --server OverField-Server --client "<国服 1.1.12 客户端目录>" --verify-all --full --output request-audit.json
```

`--verify` 运行小套件与主线/额外剧情分支回归。省略验证选项可快速对比消息定义和路由。每种操作的成功码仅证明对应样例，玩法完成度另见[剧情对照](剧情对照.md)等专项记录。
