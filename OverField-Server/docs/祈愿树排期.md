## 复开指定期数

以下 `trees.json` 在 2027 年 1 月复开童趣树，并关闭红冬树的首次排期。所有时间均为北京时间。起止边界当秒可以领取。`null` 表示采用该期原表对应的起点或终点。

```json
{
  "trees": [
    {"id": 114, "enabled": true, "opens_at": "2027-01-01 00:00:00", "closes_at": "2027-01-31 23:59:59"},
    {"id": 115, "enabled": false, "opens_at": null, "closes_at": null}
  ]
}
```

Windows 使用 `.\Start-Server.cmd admin call blessings.set --input trees.json`，Linux 使用 `./start.sh admin call blessings.set --input trees.json`。内置本地区服需要指定启动器使用的 `--state`。用 `blessings.get` 查询已生效的覆盖列表。

每次设置都替换整个祈愿树覆盖列表。省略某期会恢复该期国服日期，传 `{"trees":[]}` 可恢复全部。服务端立即按新时间判断兑换。玩家重开 OF_SF 客户端，待资源更新完成即可读取新日期。同一期曾领取过的节点会继续显示为已领。

原生协议测试覆盖了 63 期的 911 个兑换节点。在原版资源文件上，另做了独立改期核验，比较所有解压后的字节，确认只有选定期数的日期字段发生变化。

## 每日任务

第一章《“眼”》第一话的第一步（任务 101011）完成后，每个角色每天获得 4 条不同的祈愿任务。国服快照同时保存“槽位 → 任务 ID”和对应的任务状态，区服依此保存条件、进度和领取状态。每天北京时间 05:00 刷新。已完成却没领的上一批任务按邮件模板 20 合并寄出一次。[运营公告](https://www.233leyuan.com/post-detail/1932387400565501952)

达成条件时，任务和条件一起进入「已完成、待领取」，奖励仍在任务里。打开头像菜单，点祈愿任务的领取按钮，即可领取所有已完成任务的奖励。月亮按钮领取的是碎片合成的祈愿石。当天退出或重启后仍可手动领取，刷新后漏领的奖励到系统邮件中领取。

原客户端根据各个条件的状态绘制按钮。旧版 OF_SF 有些任务在达到 1/1 时已经显示灰勾，实际尚未发奖。更新后重登，区服会把当天这些任务恢复为可领取。

PC 1.1.12 的 45 条任务都使用奖励组 2000600。每条给 30 星石（102）和 2 祈愿石（125），每日四条合计 120 星石和 8 祈愿石。祈愿碎片（124）另走月亮兑换。区服目前从 38 条具备服务端完成凭据的任务中按角色和日期选取四条。六条指定地图的随机事件和一条使用互动道具的条件尚缺完成凭据，暂不派发。官方每日抽取权重未公开。

## 野外碎片

野外地图首次结算灰物击杀、打开补给箱、完成采集，以及在鱼塘成功钓到鱼时，有机会在原客户端看到对应动作的祈愿石碎片提示。碎片直接计入角色余额，箱中物品仍支持单件拾取和全部拾取。同一只箱重开、换线或重登均只判定一次；补给箱刷新后可重新判定。采集工具、点位或背包校验失败时不发碎片。

服主可通过 `rules.set` 设置 `activity_fragment_percent`（0–100，默认 20）和 `activity_fragment_quantity`（正数覆盖每次数量，默认 0 采用资源池 107 的 5 枚）。这两项是区服初始规则，官服资料确认了获得途径，尚无样本确定各动作的概率和数量。[国服活动说明](https://www.taptap.cn/game-event/8988)
