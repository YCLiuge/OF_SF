私服协议实测覆盖上表所列的操作。大部分测试直接连两个独立角色，涵盖重登、存档恢复及异常输入。原版 Unity 的各活动页面和完整主线仍需逐项实机验证。多人小游戏的完整对局、全部赛季活动、所有副本和跨区服联机尚未完成官服等价验证。

遇到差异时，记录所在玩法、点击顺序、预期结果与私服实际显示。启用阶段诊断后，可在 `stage-failures.jsonl` 查看失败请求，在 `stage-operations.jsonl` 区分同一请求中的已知操作。操作记录仅包含请求类别、枚举或已知教学事件编号，不含对话文本和账号。若需要对照官服，请只记录相同玩法的界面操作，不必向服主提供账号凭据或登录抓包。

仓库中的 `tools/compare_upstream.py` 可读取本机已有的 byzp/of-ps 源码检索专用请求处理器。例如在本仓库根目录运行 `python tools/compare_upstream.py /path/to/of-ps`。结果按请求名对比，私服通用处理器、登录分发以及运行时生成的处理器需另查源码。

上游版本有 295 个原生请求。当前客户端的 303 项请求及逐项验证情况见[客户端请求对照](客户端请求对照.md)。仍有部分邮件附件、时装染色、家园房间装饰和秘境扫荡待补。专用请求、连接层处理及通用实现的代码位置不同，实际覆盖以游戏动作和回归结果为准。[广场入口实测](广场入口实测.md)
