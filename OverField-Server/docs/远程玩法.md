# 使用自己服务器上的角色

在远端解压服务端，使用 Create-Player.cmd 或 ./start.sh create-player 创建独立档案，再启动服务。远端的 OF_BIND 和 OF_GAME_HOST 均可保留为 127.0.0.1。将创建命令生成的私服档案 JSON 通过自己的安全渠道复制到游戏电脑。保存其中密钥的人能登录这个私服角色。

游戏电脑需要可用的 OpenSSH 客户端。先用自己的 SSH 账号配置密钥登录，并通过服务器管理员提供的主机密钥指纹确认目标主机。执行 ssh -o BatchMode=yes -o StrictHostKeyChecking=yes 用户@主机 true 应能正常退出。服务器需要允许该账号转发到本机的档案和玩法两个端口。已有 SSH 主机别名也可使用。

在游戏电脑的独立区服启动器中选择远端档案和 SSH 目标，启动游戏。原版客户端仍连接自己电脑上的本地区服。完成本机身份验证后，本机使用所选档案向远端私服申请一次性票据。两个 SSH 通道仅连接所选主机的回环档案和玩法服务。角色、装备、任务和场景保存于远端，客户端的界面偏好保存在本机与该远端档案对应的独立设置中。

## 手动启动本机端

在本机为此远端档案使用独立 OF_STATE 目录。设定以下环境变量后用本机服务端启动命令运行。远端服务端使用默认独立私服身份配置即可。

| 变量 | 用途 |
| --- | --- |
| OF_REMOTE_SSH_TARGET | SSH 的 user@host 或预配置主机别名 |
| OF_REMOTE_PROFILE | 远端私服导出的个人档案 JSON 的绝对路径 |
| OF_REMOTE_SSH_PORT | 可选 SSH 端口，默认遵从 OpenSSH 配置 |
| OF_REMOTE_HTTP_PORT | 所选 SSH 服务器回环上的档案端口，默认 18881 |
| OF_REMOTE_GAME_PORT | 所选 SSH 服务器回环上的玩法端口，默认 11033 |
| OF_REMOTE_LOCAL_SLOT | 已知时填准许使用远端档案的本机私服角色槽位 |
| OF_REMOTE_PAIR_FIRST | 设置为 1 时，可将首次通过验证的本机唯一角色与所选远端档案配对 |
| OF_REMOTE_SSH_CONFIG | 可选，自有 OpenSSH 配置文件的绝对路径 |

已配对的远端档案仅供原本的本机角色使用。多人机器或已有多份本机档案时，请明确指定 OF_REMOTE_LOCAL_SLOT。远端私服关闭或凭据无效时，本机前端会拒绝该次游戏登录。迁移远端角色可使用服务端的 backup 与 restore，并单独保管该玩家的档案 JSON。

## 迁移现在的角色

本机用原版客户端开始游戏后，会在本服生成独立角色。要在远端继续玩同一个角色，请先退出游戏并正常停服，再用当前角色的存档目录运行下列命令。Windows 示例中的路径需要替换成实际位置。

~~~powershell
.\Start-Server.cmd --state "D:\OverField\我的私服\State\realm" issue-profile --out "D:\OverField\我的私服角色.json"
.\Start-Server.cmd --state "D:\OverField\我的私服\State\realm" backup "D:\OverField\角色存档.zip"
~~~

把备份复制到目标主机，用相同版本服务端的 restore 命令恢复后启动。将刚签发的玩家 JSON 保留在游戏电脑，并在 SSH 设置中选中。新私服密钥的摘要和角色进度会随此备份迁移。已有备份也可先在目标主机恢复，再用该主机的 issue-profile 为同一个角色签发私服档案。

默认选择唯一已玩且已绑定的本服角色。若有多个候选，在 issue-profile 后加入 --nickname "游戏内昵称"，必要时用 --slot 指定准确的本服角色槽位。管理员可以为同一角色签发额外的游戏密钥，每份都应选用新的输出文件名并单独保管。Windows 输出文件限制为执行命令的本地账户读取，Linux 权限为 0600。
