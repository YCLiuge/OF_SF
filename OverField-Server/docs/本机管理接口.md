# 本机管理接口

在服务端目录运行。Windows 使用 `Start-Server.cmd`，Linux x86-64 使用 `./start.sh`。同一套命令支持脚本、桌面管理器和 agent。选定存档时，将 `--state 路径` 放在 `admin` 前面。日常启动沿用 `start`。

| 命令 | 用途 |
| --- | --- |
| `admin schema` | 返回操作列表、可用状态和每个操作的 JSON 输入格式 |
| `admin status` | 查看本机运行状态、存档位置、数据库内账号数和角色数 |
| `admin call 操作 --input 文件.json` | 从 UTF-8 文件读取参数并执行操作 |
| `admin call 操作` | 从标准输入读取一个 UTF-8 JSON 对象，无参数操作传入 `{}` |

命令输出一行 JSON，接口版本为 `overfield.admin/v1`。成功时退出码为 0，结果在 `result`。失败时退出码为 1，读取 `error.code` 和 `error.message`。首次启动前状态为 `uninitialized`。运行中的区服会显示 `running`，正常关服后为 `stopped`。进程异常退出后，存留的启动标记显示为 `stale`。启动中显示 `busy`。表尚未建立，或启动迁移暂时独占数据库时，相应计数显示为 `null`，启动结束后恢复。

## 网页管理台

在服务端浏览器打开 `http://127.0.0.1:端口/admin/`，输入当前进程的 `OF_ADMIN_TOKEN`。首页显示在线连接、上限、账号数和角色数。侧栏分为运行与维护、玩家与社区、邮件与奖励、活动与舞台、招募与祈愿、公告与版本六组，支持按中文或接口名搜索。配置修改遇到他人先保存时，先重新读取再编辑。

**发奖励。** 进入「投递游戏邮件」或「创建兑换码」，输入部分中文名称或选择分类，勾选物品并在「已选物品」设置数量。每次最多 16 种，切换搜索条件保留已选项。邮件可只发正文，范围可选指定账号、已有玩家或包含有效期内的新玩家。提交前核对范围和数量。投递记录与兑换码列表可按名称查看奖励。

**管理招募。** 在「招募 · 内容目录」按角色、卡池名或复刻期次筛选。选中卡片可看区服状态、招募券、原版排期和保底。「开启卡池」选择要开的那一期并确认。「招募池与概率」可调整保底和各奖励组的百分比，合计须为 100%。卡面上印的原版活动日期与当前区服的启用状态分别显示。

**安排活动。** 在「活动排期」「祈愿树排期」「舞台与活动入口」按名称选择活动、入口和奖励，核对北京时间后保存。通过「查看已发布内容」可按标题找到公告并编辑或撤回。在照片墙和举报列表可按记录直接处理。

**维护目录。** 奖励目录按发放方式过滤可领取模板，数量上限与服务端发奖校验共用。简体中文名称索引随服务端包分发。用旧资源包构建时，在仓库根目录运行 `python tools/export_reward_names.py String_Simplified.json --items 旧包路径/resources/data/Item.json`，再执行原有 hydrate 与打包流程。导出器校验物品表和名称索引。当前版本 11,483 个模板中有 11,099 个具备正式简中名称，其余显示「未命名物品」及编号。

前端使用原生 Web Components 与 ES 模块，静态资源随包提供。页面和 CLI 共用服主权限与操作定义，停服操作使用 CLI。刷新页面或断开后需要重新输入令牌。

## 兑换码与照片

`codes.issue` 可在运行中发行本服兑换码。下面的参数设置总计 100 个名额，每个角色可兑换一次。时间使用北京时间。总名额为 0 即不限总数。用 `codes.list` 查看已发行的码，`codes.withdraw` 可停止后续兑换。省略 `kind` 时，玩家从普通兑换码入口领取。要发行原生继承奖励码，在参数中加入 `"kind":"inherit"`。两种码分别通过各自的请求领取，领取奖励仅增加当前角色的物品。导入旧账号进度见[个人进度导入](个人进度导入.md)。

```json
{"code":"ROTA2026","quota":100,"expires_at":"2026-12-31 23:59:59","rewards":[{"item":101,"quantity":5000}]}
```

`photos.list` 按发布时间倒序返回照片，可用 `limit` 指定每页数量、用 `before` 传入上一页最后的分享码。服主可用 `photos.withdraw` 和 `code` 撤回单张照片。

玩家在游戏里提交的举报进入本服管理队列。用 `reports.list` 分页查看，`reports.resolve` 标记已处理，查询 `resolved=true` 可复查历史。照片举报会校验作品与发布者的对应关系。

## 服主示例

```powershell
.\Start-Server.cmd admin status
.\Start-Server.cmd admin schema
.\Start-Server.cmd admin call notice.publish --input notice.json
'{}' | .\Start-Server.cmd admin call maintenance.list
```

下面的 `notice.json` 会发布一条带海报的活动公告。

```json
{"title":"周末活动","body":"本周六 20:00 开始。","images":["posters/weekend.png"]}
```

`notice.edit` 用数值 `id` 指定公告。省略 `images` 会保留配图，传入空数组可清空配图。图片和安装包路径相对于命令执行目录，也可使用绝对路径。

```sh
printf '%s' '{}' | ./start.sh admin call realm.stop
./start.sh admin status
# 确认 lifecycle 为 stopped 后执行下列命令
printf '%s' '{"world_max":3000}' | ./start.sh admin call rules.set
printf '%s' '{"archive":"./realm.zip"}' | ./start.sh admin call state.backup
printf '%s' '{"archive":"./realm.zip"}' | ./start.sh --state ./migrated admin call state.restore
```

发布公告和版本支持在线执行。更改玩法规则、备份或还原需要停服。`realm.stop` 发送正常关服请求，可用 `admin status` 确认状态变为 `stopped`。还原目的地须为空或尚未创建。管理操作由本机文件系统权限控制。

## 本机 HTTP 管理

设置 `OF_ADMIN_PORT` 和独立的 `OF_ADMIN_TOKEN` 后启动区服。管理端口只监听 `127.0.0.1`，须与游戏端口、玩家 HTTP 端口各不相同。默认使用现有 CLI。持有令牌的进程拥有服主权限，可以发布本机文件和请求关服。将令牌只交给受信任的本机工具。

Windows PowerShell 中可这样生成令牌并启动。把同一个令牌通过本机工具的凭据设置提供给调用方。

```powershell
$env:OF_ADMIN_PORT = "18882"
$env:OF_ADMIN_TOKEN = .\runtime-win64\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
.\Start-Server.cmd start
```

Linux x86-64 启动示例。

```sh
export OF_ADMIN_PORT=18882
export OF_ADMIN_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
./start.sh start
```

所有请求都使用 `Authorization: Bearer <令牌>`。调用方在自己的环境中设置相同的 `OF_ADMIN_TOKEN` 后，可以这样读取运行状态。

```powershell
$base = 'http://127.0.0.1:18882/admin/v1'
$headers = @{Authorization = "Bearer $env:OF_ADMIN_TOKEN"}
Invoke-RestMethod "$base/operations/realm.status" -Headers $headers
Invoke-RestMethod "$base/operations/notice.publish" -Method Post -Headers $headers `
  -ContentType 'application/json; charset=utf-8' -Body '{"title":"维护","body":"周六更新"}'
```

| 路径 | 用途 |
| --- | --- |
| `GET /admin/v1/openapi.json` | 获取可直接导入的 OpenAPI 3.1 文档 |
| `GET /admin/v1/schema` | 获取与 `admin schema` 相同的操作列表及输入定义 |
| `GET /admin/v1/operations/{操作}` | 读取 `readOnly` 操作的结果 |
| `POST /admin/v1/operations/{操作}` | 执行写操作，传 UTF-8 JSON 对象，无参数写操作传 `{}` |

操作沿用 CLI 的结果格式和 64 KiB 输入上限。HTTP 401 表示令牌缺失或无效，409 表示状态冲突。备份、恢复、修改玩法规则需停服后运行 CLI。发布公告配图和版本包可使用区服进程能读取的本机文件，建议填写绝对路径。HTTP 接口拒绝 URL、UNC 共享和 Windows 设备命名空间路径。

## 招募池

`gacha.enable` 只上架指定的 UP 池，接受如 `{"id":3002}` 的参数。它保留其他卡池和已有权重。

`gacha.catalog` 列出当前国服版本认识的卡池和奖励组。`gacha.get` 返回本服设置。`gacha.set` 接收完整的 `pools` 配置并原子替换。调整前保留一份当前配置，以便恢复。在 PowerShell 中可直接导出可编辑的参数，Windows PowerShell 5 和 PowerShell 7 均可读取该文件。

```powershell
$json = '{}' | .\Start-Server.cmd admin call gacha.get | ConvertFrom-Json
$json.result | ConvertTo-Json -Depth 12 | Set-Content -Encoding utf8 pools.json
# 编辑 pools.json 中的 enabled、pity 和 weights 后应用
.\Start-Server.cmd admin call gacha.set --input pools.json
```

见 [招募卡池](招募卡池.md)。
